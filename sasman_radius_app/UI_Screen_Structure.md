# هيكل شاشات واجهة `sasman_radius_app`

هذا الملف يصف هيكل الواجهات الحالي لتطبيق Flutter الموجود في `sasman_radius_app`، مناسب لإرساله إلى مصمم UI/UX لتطوير التصميم الاحترافي.

---

## 1. مسار الدخول (Entry Flow)

1. **Splash Screen** (`lib/screens/splash_screen.dart`)
   - شاشة تحميل بسيطة.
   - تحدد إن كان هناك عنوان خادم مخزن.
   - إذا كان العنوان غير موجود أو فارغ، تنتقل إلى شاشة إعداد الخادم.
   - إذا كان العنوان موجودًا، تنتقل إلى شاشة تسجيل الدخول.

2. **Server Setup Screen** (`lib/screens/auth/server_setup_screen.dart`)
   - بطاقة مركزية داخل `GradientBackground`.
   - مدخلان:
     - `عنوان السيرفر أو IP`.
     - `رابط Cloudflare اختياري`.
   - جملة نصية توضح أن رابط Cloudflare يُستخدم بدل IP عند إدخاله.
   - أزرار:
     - `اختبار الاتصال`.
     - `حفظ ومتابعة`.
   - يعرض رسالة نجاح أو خطأ.

3. **Login Screen** (`lib/screens/auth/login_screen.dart`)
   - بطاقة تسجيل دخول على خلفية متدرجة.
   - يظهر شعار/أيقونة التطبيق.
   - حقول:
     - اسم المستخدم.
     - كلمة المرور مع زر إظهار/إخفاء.
   - زر تسجيل دخول.
   - زر الانتقال إلى تغيير عنوان السيرفر.
   - عرض عنوان السيرفر الحالي تحت العنوان إذا كان موجودًا.

---

## 2. الهيكل العام للشاشة الرئيسية (Admin Shell)

### 2.1. الشاشة الرئيسية للتطبيق

- الملف: `lib/screens/home/admin_shell_screen.dart`
- تتألف من:
  - شريط أعلى `AppBar` بعنوان ديناميكي: `SASMAN RADIUS - <اسم القسم>`.
  - زر تحديث.
  - زر خروج.
- اعتمادًا على العرض:
  - العرض الكبير (`>= 980px`): شريط تنقل جانبي ثابت مع محتوى في الجانب الأيمن.
  - العرض الصغير: درج تنقل `NavigationDrawer` يفتح من اليسار.

### 2.2. قائمة الأقسام

الأقسام المتاحة:
- `الرئيسية` (Dashboard)
- `المشتركين` (Users)
- `الباقات` (Profiles)
- `الكروت` (Vouchers)
- `NAS`
- `البث` (Streams)
- `واتساب` (WhatsApp)
- `السجلات` (Logs)
- `الإعدادات` (Settings)

### 2.3. نمط العرض

- كل قسم يعرض `Scaffold` داخليًا.
- تعيين وحدة عرض ضمن `body`.
- معظم الشاشات تستخدم:
  - عنوان رئيسي.
  - وصف صغير.
  - بحث نصي.
  - قائمة عناصر.
  - زر إجراء رئيسي.
  - دعم تحديث بالسحب `RefreshIndicator`.

---

## 3. وصف الشاشات الفرعية

### 3.1. شاشة Dashboard

- الملف: `lib/screens/admin/dashboard_screen.dart`
- صفحة إحصائيات.
- تستدعي API لجلب المشتركين وبيانات الحساب.
- تعرض بطاقات إحصائية:
  - إجمالي المشتركين.
  - المشتركين النشطين.
  - المتصلين الآن.
  - المشتركين المنتهين.
  - المشتركين القريبين من الانتهاء.
  - الرصيد.
- تحتوي على `RefreshIndicator` لإعادة التحميل.

### 3.2. شاشة المشتركين (Users)

- الملف: `lib/screens/admin/users/users_screen.dart`
- وظائف رئيسية:
  - قائمة مشتركين قابلة للبحث.
  - إضافة مشترك جديد.
  - تعديل مشترك.
  - حذف مشترك.
  - تجديد اشتراك.
  - عرض تفاصيل مشترك.
  - تبديل حالة المشترك (تشغيل/إيقاف).
  - فصل المشترك (disconnect).
- كل عنصر مشترك يعرض:
  - اسم المستخدم.
  - حالة النشاط.
  - باقة.
  - تاريخ الانتهاء.
  - الرصيد.
- النوافذ المنبثقة:
  - نموذج الإضافة/التعديل.
  - نافذة تأكيد الحذف.
  - نافذة تجديد الاشتراك.
  - نافذة عرض التفاصيل.

### 3.3. شاشة الباقات (Profiles)

- الملف: `lib/screens/admin/profiles/profiles_screen.dart`
- وظائف رئيسية:
  - قائمة باقات قابلة للبحث.
  - إضافة باقة جديدة.
  - تعديل باقة.
  - حذف باقة.
- لكل باقة تستعرض:
  - الاسم.
  - السعر.
  - سرعة التحميل/الرفع.
  - صلاحية الأيام.
  - NAS الافتراضي.
  - عدد الأجهزة المتزامنة.
- نموذج الإضافة/التعديل يحتوي على:
  - اسم الباقة.
  - سرعات التحميل والرفع.
  - نوع ارتباط MikroTik (`pool` أو `group` أو بدون ارتباط).
  - صلاحية (أيام).
  - السعر وسعر الوكيل.
  - NAS-IP-Address.
  - عدد الأجهزة المتزامنة.
  - إعدادات التعامل مع المشتركين المنتهين (`expired pool` / `expired profile`).

### 3.4. شاشة الكروت (Vouchers)

- الملف: `lib/screens/admin/vouchers/vouchers_screen.dart`
- وظائف رئيسية:
  - عرض قائمة كروت الشحن.
  - بحث في الكروت.
  - توليد كروت جديدة.
  - حذف كرت.
- نموذج توليد الكروت يحتوي على:
  - اختيار الباقة.
  - عدد الكروت.
  - سعر الكرت.
  - نوع الكود (`حروف وأرقام`، `أرقام فقط`، `حروف فقط`).
  - طول الكود.
- تعرض حالة الكرت (`متاح` أو `مستخدم`).

### 3.5. شاشة NAS

- الملف: `lib/screens/admin/nas/nas_screen.dart`
- وظائف رئيسية:
  - عرض قائمة أجهزة NAS.
  - بحث في NAS.
  - إضافة NAS جديد.
  - تعديل NAS.
  - حذف NAS.
  - إعداد سريع.
- لكل جهاز NAS تعرض:
  - IP العميل.
  - الاسم.
  - `NAS-IP-Address` المربوطة.
  - حالة Global.
- نموذج NAS يحتوي على:
  - IP.
  - اسم.
  - RADIUS Secret.
  - `NAS-IP-Address`.
  - اختيار ما إذا كان مرئيًا لجميع الوكلاء.

### 3.6. شاشة البث (Streams)

- الملف: `lib/screens/admin/streams/streams_screen.dart`
- وظائف رئيسية:
  - عرض قائمة خدمات البث.
  - بحث في البث.
  - زر `إضافة مصدر` (حالياً بدون تنفيذ).
  - تفعيل/إيقاف كل خدمة بث.
- لكل مصدر بث يعرض:
  - اسم المصدر أو الـ `source`.
  - الحالة.
  - زر تبديل الحالة.

### 3.7. شاشة WhatsApp

- الملف: `lib/screens/admin/whatsapp/whatsapp_screen.dart`
- وظائف رئيسية:
  - تحميل إعدادات WhatsApp.
  - عرض حالة التكامل.
  - قوالب الرسائل.
  - تحرير الإعدادات.
- شاشة الإعداد تحتوي على:
  - رقم الحساب.
  - توكن API.
  - قالب الرسالة.
  - مفتاح تفعيل/تعطيل الخدمة.
- العرض بعد التحميل يظهر حالة التفعيل ونقاط البيانات الأساسية.

### 3.8. شاشة السجلات (Logs)

- الملف: `lib/screens/admin/logs/logs_screen.dart`
- وظائف رئيسية:
  - عرض سجلات النظام.
  - بحث ضمن السجلات.
  - إعادة تحميل.
- لكل سجل يتم عرض:
  - الرسالة أو الحدث.
  - الطابع الزمني.
  - تفاصيل إضافية منظمة عبر `StructuredDetailsView`.

### 3.9. شاشة الإعدادات (Settings)

- جزء من `lib/screens/home/admin_shell_screen.dart`.
- تعرض:
  - عنوان السيرفر الحالي.
  - زر تعديل عنوان السيرفر.
  - زر تسجيل خروج.

## 4. ملاحظات على واجهة المستخدم الحالية

- اللغة: واجهة عربية بالكامل باستثناء بعض النصوص التقنية المحدودة.
- نمط التصميم الحالي:
  - واجهة بطاقة (`Card`) لكل نموذج أو عنصر رئيسي.
  - أزرار رئيسية ملونة وأزرار ثانوية `Outlined`.
  - استخدام `TextField` و `DropdownButtonFormField` و `SwitchListTile` و `Checkbox` في النماذج.
  - التباعد الداخلي جيد، لكن التصميم يبدو وظيفيًا أكثر منه بصريًا حديثًا.
  - لا يوجد تقسيم واضح بين الأقسام المتقدمة مثل الباقات وNAS من حيث واجهة المستخدم.

- تحسينات مقترحة للمصمم:
  - تطوير نظام ألوان ثابت وواضح مع تفريق أكبر بين الحالات.
  - تحسين شريط التنقل الجانبي/الدروج ليكون أكثر وضوحًا وتمايزًا.
  - تطوير تجربة البطاقات في الصفحات الرئيسية مثل `Dashboard` و `Users` و `Profiles`.
  - جعل النماذج (dialogs) أكثر انسجامًا وتقديم حالة حقيقية للمدخلات الخاطئة.
  - توحيد نمط أزرار الإجراء وحجم الخطوط.
  - إضافة أيقونات ومؤثرات مرئية للتمييز بين الحسابات وعنصرات التحكم.

يمكن للمصمم أن يستخدم هذا الهيكل كأساس لإنشاء:
